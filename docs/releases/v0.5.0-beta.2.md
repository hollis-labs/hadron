## External workflow engine qualification boundary

This immutable prerelease publishes the complete public
`github.com/hollis-labs/hadron/workflow/...` package tree for external
qualification. Nanite may pin
`github.com/hollis-labs/hadron v0.5.0-beta.2` as the first non-Hadron durable
host pilot.

This release supersedes `v0.5.0-beta.1` for new qualification work. The code
boundary is unchanged; `v0.5.0-beta.2` corrects the tagged adoption guide and
external example so compensation-capable hosts use the exhaustive conformance
entry point.

This remains a qualification boundary inside the Hadron module. It is not a
standalone workflow module extraction and does not claim post-v1 API stability.

### Conformance entry points

- `conformance.RunRequired` covers compiler/source maps, state values,
  scheduling and control flow, waits, and step-kind metadata.
- `conformance.RunComplete` preserves the pre-compensation host contract and
  adds verification and memoization.
- `conformance.RunExhaustive` requires `conformance.CompensationHost` and adds
  the durable compensation fixture family. A durable host that enables
  compensation should use this as its final conformance gate.

Fixture factories must exercise the downstream implementation against the
opaque inputs. A factory that merely echoes fixture expectations demonstrates
harness wiring, not host conformance.

### Included boundary and host obligations

- Graph-native source contracts, compiler and validation phases, generated
  graph and execution-plan schemas, source maps, and immutable plan digests.
- Typed values, artifact references, waits, gates, verification, retries,
  fan-out, control flow, recovery/replay, memoization, reactors, services, and
  durable graph-visible compensation contracts.
- Public exact-version step-kind and verifier registries, optional adapters,
  the canonical offline embedding loop, and the in-memory reference store.
- Public API and dependency/import guards that keep Hadron application
  internals and sibling-product semantics out of `workflow/...`.

A durable host owns database migrations, CAS/idempotency/event correctness,
timer recovery, policy, executor catalogs, artifacts, credentials, and product
presentation. `workflow/runtime/inmemory` is a concurrency-safe reference
store, not crash-durable storage. Consumers must pin this exact tag and must
not infer compatibility, select an implicit latest version, or use a
pseudo-version in production.

See [the tagged adoption guide](https://github.com/hollis-labs/hadron/blob/v0.5.0-beta.2/docs/workflow-engine-adoption.md)
for the embedding and qualification sequence.
