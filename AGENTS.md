# hadron

The new Hadron: a local-first daemon and CLI for typed durable workflow graphs, built on the Substrate framework. A parallel build; it replaces `hollis-labs/hadron` only when the owner decides it is ready, at which point this repository is renamed to `hadron`. The Go module path is already `github.com/hollis-labs/hadron`.
Not: a port of the old app's API, schema or auth, a place for framework code (that is Substrate), or anything carried forward for compatibility.

## Start here

- `cmd/hadron/substrate.yaml` — the manifest: modules and config. The shell (config, logging, health, HTTP, auth, policy, MCP, database, scheduler, events, CLI skeleton) comes from here, not from code.
- `cmd/hadron/` — the app's own commands: `serve`, `mcp`, `workflow`, `build`.
- `internal/runtime` — the composition root: the engine host, workers, identity, access (exposure profiles). `internal/api`, `internal/mcptools`, `internal/a2a` are the transports; `internal/appworkflow`, `internal/persistence` the engine host and its state.
- `README.md` and `docs/` — operator documentation (getting started, workflows, CLI, configuration, access, MCP, operations). Keep them true to the code when behaviour changes; `docs/status.md` and `docs/parity.md` are the development record.
- `cmd/hadron/substrate_wiring.go` — GENERATED by `substrate generate`; edit the manifest, not this file.
- `docs/status.md` — what is ported and what is not. The plan is Tesseract `project/substrate-framework/workspace/design` `plan_hadron_port_to_substrate_20261104`.

## Commands

```sh
go vet ./... && go test ./... && golangci-lint run
python3 scripts/scan-public --ref HEAD
go run github.com/hollis-labs/substrate/cmd/substrate@<version> generate -f cmd/hadron/substrate.yaml
go run github.com/hollis-labs/substrate/cmd/substrate@<version> upgrade -dry-run
```

## Boundaries

- Substrate is the line in the sand: the framework supplies the mechanism, this app owns process and data. When the app does not fit the framework, the choice is, in order: add the capability to Substrate, remove the capability from the app, or record an explicit exception here.
- No shims, no fallbacks, no backwards compatibility with the old Hadron (its `/v1` API, `localauth`, schema, `HADRON_*` variables). Routes are `/api/...` with flat errors; auth is the framework's (Tether-issued tokens, per-app dial `HOLLIS_AUTH_HADRON`).
- Ported code follows current naming and patterns. Anything that does not is listed in `docs/status.md` under "Cleanup", not fixed silently.
- Dropped on purpose: sysop-ui, `hadron-app`, the archive packages (blueprint, pipeline, lint, schemas, spec-v04).
- Execution semantics (claims, workers) stay app code unless the port shows a plain job queue fits.
- Pins live in Substrate's BOM; this module follows the Substrate version it requires. The repo is private until cutover but is scanned as if public: no secrets, internal hosts or personal paths.
